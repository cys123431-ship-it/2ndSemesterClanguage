# 03. 배열 생성·정렬·순차 탐색·이진 탐색 — 8~11장 응용 버전 상세 해설

> **별도 응용판**: 기존 03_ArraySearch의 main.c, function.c, function.h를 그대로 보존했습니다. 응용판의 세 파일을 아래에 **전문 그대로** 수록합니다.

## 1. 왜 새로운 기능을 추가했나?

원본은 난수 배열을 만든 뒤 정렬하고 **이진 탐색**을 수행했습니다. 그런데 학생이 정렬의 이유를 깊게 이해하려면 **정렬 없이도 가능한 탐색**과 비교해 보면 좋습니다.

따라서 응용판에는 **LinearSearch(순차 탐색)**를 추가했습니다. 동일한 숫자를 정렬 **전**에 순차 탐색하고, 정렬 **후**에 이진 탐색합니다.

핵심 학습 질문: **왜 순차 탐색은 정렬이 필요 없는데 이진 탐색은 정렬이 필요할까?**

응용판에서는 검색할 값 입력을 main이 담당하고, 검색 함수들은 **찾은 인덱스 또는 -1**만 돌려주도록 바꿔 반환값 개념을 연습합니다. 1~11장만으로 이해할 수 있는 구조이며, 재귀·동적 메모리·전역변수는 쓰지 않습니다.

## 2. 세 파일의 전체 코드 — 저장된 응용판과 동일

### Applied_8to11/03_ArraySearch/main.c

~~~c
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
#include "function.h"

int main(void)
{
    int list[SIZE];
    int key, linearIndex, binaryIndex;

    MakerArr(list);

    printf("정렬 전 배열: ");
    PrnArr(list);

    printf("찾을 정수: ");
    if (scanf("%d", &key) != 1)
    {
        printf("정수를 입력해야 합니다.\n");
        return 1;
    }

    // 처음 배열에서도 가능한 순차 탐색입니다.
    linearIndex = LinearSearch(list, key);

    SortArr(list);
    printf("정렬 후 배열: ");
    PrnArr(list);

    // 이진 탐색은 반드시 정렬한 다음에 사용합니다.
    binaryIndex = BinarySearch(list, key);

    if (linearIndex == -1)
    {
        printf("순차 탐색: 찾지 못했습니다.\n");
    }
    else
    {
        printf("순차 탐색: 정렬 전 list[%d]에서 찾았습니다.\n", linearIndex);
    }

    if (binaryIndex == -1)
    {
        printf("이진 탐색: 찾지 못했습니다.\n");
    }
    else
    {
        printf("이진 탐색: 정렬 후 list[%d]에서 찾았습니다.\n", binaryIndex);
    }

    return 0;
}
~~~


### Applied_8to11/03_ArraySearch/function.h

~~~c
#ifndef FUNCTION_H
#define FUNCTION_H

#define SIZE 10

void MakerArr(int list[]);
void PrnArr(int list[]);
void SortArr(int list[]);
int LinearSearch(int list[], int key);
int BinarySearch(int list[], int key);

#endif
~~~


### Applied_8to11/03_ArraySearch/function.c

~~~c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include "function.h"

// 0부터 99까지의 난수 10개로 배열을 채웁니다.
void MakerArr(int list[])
{
    int i;

    srand((unsigned int)time(NULL));

    for (i = 0; i < SIZE; i++)
    {
        list[i] = rand() % 100;
    }
}

// 현재 배열 내용을 출력합니다.
void PrnArr(int list[])
{
    int i;

    for (i = 0; i < SIZE; i++)
    {
        printf("%d  ", list[i]);
    }
    printf("\n");
}

// 정렬하지 않은 배열에서도 사용할 수 있는 순차 탐색입니다.
int LinearSearch(int list[], int key)
{
    int i;

    for (i = 0; i < SIZE; i++)
    {
        if (list[i] == key)
        {
            return i;
        }
    }

    return -1;
}

// 가장 작은 원소를 앞쪽으로 옮기는 선택 정렬입니다.
void SortArr(int list[])
{
    int i, j, min, temp;

    for (i = 0; i < SIZE - 1; i++)
    {
        min = i;

        for (j = i + 1; j < SIZE; j++)
        {
            if (list[j] < list[min])
            {
                min = j;
            }
        }

        temp = list[i];
        list[i] = list[min];
        list[min] = temp;
    }
}

// 정렬된 배열에서 가운데 값을 비교하며 범위를 좁힙니다.
int BinarySearch(int list[], int key)
{
    int low = 0;
    int high = SIZE - 1;
    int mid;
    int count = 1;

    while (low <= high)
    {
        mid = (low + high) / 2;
        printf("%d회: low=%d, mid=%d, high=%d, list[mid]=%d\n",
               count, low, mid, high, list[mid]);

        if (list[mid] == key)
        {
            return mid;
        }
        else if (list[mid] > key)
        {
            high = mid - 1;
        }
        else
        {
            low = mid + 1;
        }

        count++;
    }

    return -1;
}
~~~


## 3. 세 파일이 필요한 이유와 호출 관계

**main.c**는 실행 순서를 결정합니다. 사용자에게 값을 묻고, 두 탐색 함수의 반환값을 출력합니다.

**function.h**는 함수가 어느 이름과 인자를 가지는지 알려줍니다. 위쪽의 **#ifndef FUNCTION_H / #define FUNCTION_H / #endif**는 헤더가 실수로 두 번 포함되더라도 선언이 중복 처리되지 않게 하는 간단한 방지문입니다. 중요한 것은 이 부분이 **변수가 아니라 전처리 조건**이라는 점입니다.

**function.c**는 실제 난수 생성, 출력, 순차 탐색, 선택 정렬, 이진 탐색의 계산을 수행합니다.

~~~text
main의 list[10]
    |
    +-> MakerArr(list)             배열 채우기
    +-> PrnArr(list)               정렬 전 내용 확인
    +-> LinearSearch(list, key)    정렬 전 찾기
    +-> SortArr(list)              선택 정렬
    +-> PrnArr(list)               정렬 후 내용 확인
    +-> BinarySearch(list, key)    정렬 후 찾기
main은 두 검색 결과를 사용자에게 출력
~~~

이 구조가 필요한 이유는 여러 파일에 나눈 것이 과제 점수에 유리해서가 아니라 **함수의 선언과 실제 동작, 호출 관계를 구분**하려는 데 있습니다. 세 파일을 컴파일할 때는 main.c와 function.c를 함께 사용합니다.

## 4. main.c 세부 해설

### 4-1. 주요 변수

- **int list[SIZE]**: main에서 실제 정수 배열 10개를 선언합니다.
- **key**: 검색하려는 정수. 프로그램이 한 번 입력받아 두 탐색 함수에 똑같이 전달합니다.
- **linearIndex**: 정렬 전 순차 탐색 결과.
- **binaryIndex**: 정렬 후 이진 탐색 결과.

두 인덱스 값은 **서로 다를 수 있습니다**. 정렬 전과 정렬 후에는 배열의 숫자 순서가 다르기 때문입니다.

### 4-2. 왜 순차 탐색을 먼저 하는가?

**LinearSearch(list, key)**는 배열을 0번부터 하나씩 확인하므로 정렬이 필요 없습니다. 원래 숫자 순서를 보존한 상태에서 찾은 위치를 기록합니다.

그다음 SortArr로 정렬하고 BinarySearch를 호출합니다. **두 함수의 결과를 비교**함으로써 각각의 사용 조건을 이해할 수 있습니다.

### 4-3. -1을 찾지 못했다는 약속으로 사용하는 이유

배열의 유효 인덱스는 **0~9**입니다. 그래서 **-1은 존재할 수 없는 인덱스**입니다.

함수가 -1을 반환하면 '찾지 못함'으로 해석합니다. 0을 실패 표시로 쓰면 실제로 **첫 번째 칸에서 찾은 상황**과 구별할 수 없으므로 -1이 적절합니다.

### 4-4. 입력 검증과 &key

**scanf("%d", &key)**는 key를 저장할 주소를 전달합니다. 값을 한 개 읽지 못하면 종료해 잘못된 검색값으로 탐색하지 않도록 합니다. 숫자 입력에는 공백이 먼저 있어도 scanf가 건너뜁니다.

## 5. function.c에서 각 함수가 필요한 이유

### 5-1. MakerArr — 난수 배열 채우기

**srand((unsigned int)time(NULL))**는 현재 시간을 난수 시작값으로 사용하고, **rand() % 100**은 0~99 정수를 만듭니다.

**for (i=0; i<SIZE; i++)**를 사용해 10개를 채웁니다. 출력되는 수는 실행마다 바뀔 수 있으므로 과제 시연에서 값이 지난번과 다르더라도 오류는 아닙니다.

중복값이 나올 수 있어 같은 수가 두 칸 이상에 존재할 수 있습니다.

### 5-2. PrnArr — 같은 출력을 두 번 사용

정렬 전과 후에 동일한 방식으로 출력해 차이를 비교합니다. 코드 복사 없이 한 함수를 두 번 호출합니다. **void**는 계산값 반환이 없는 함수라는 뜻입니다.

### 5-3. LinearSearch — 처음부터 하나씩 비교

~~~c
for (i = 0; i < SIZE; i++)
{
    if (list[i] == key)
    {
        return i;
    }
}
return -1;
~~~

이 코드는 맨 앞 원소부터 검사하다가 같으면 해당 위치를 반환합니다. 마지막까지 일치하지 않으면 -1을 반환합니다.

배열 크기가 10이라면 **운이 좋으면 1번 비교**, 맨 끝이거나 값이 없으면 **10번까지 비교**할 수 있습니다. 어떤 순서로 정렬되어 있든 상관없습니다.

### 5-4. SortArr — 선택 정렬

바깥 for문은 이번에 가장 작은 값을 배치할 인덱스 i를 정합니다. **min=i**로 현재 후보를 잡고, 안쪽 for문이 나머지 부분을 훑어 더 작은 값의 인덱스를 발견하면 min을 변경합니다.

**temp**는 교환 작업에서 값을 잠깐 보존하는 변수입니다.

~~~text
정렬 전: [8, 3, 6]
첫 번째 위치의 최솟값: 3(인덱스 1)
8과 3을 바꿈 → [3, 8, 6]
두 번째 위치의 최솟값: 6(인덱스 2)
8과 6을 바꿈 → [3, 6, 8]
~~~

**왜 i < SIZE - 1인가?** 마지막 원소는 앞 원소들을 모두 제자리에 배치하고 나면 자동으로 자기 위치에 남기 때문입니다.

### 5-5. BinarySearch — 가운데를 기준으로 범위 줄이기

- **low=0**: 왼쪽 시작.
- **high=SIZE-1**: 오른쪽 끝.
- **mid=(low+high)/2**: 이번에 확인할 가운데 인덱스.
- **if (list[mid] == key)**: 찾았으므로 인덱스를 즉시 반환.
- **else if (list[mid] > key)**: key가 더 작으므로 **high=mid-1**, 왼쪽만 계속.
- **else**: key가 더 크므로 **low=mid+1**, 오른쪽만 계속.
- **while(low <= high)**: 남아 있는 탐색 구간이 있을 때만 비교.
- 다 확인했는데 없으면 **return -1**.

여기서 **high=mid-1 / low=mid+1**이 중요한 이유는 이미 비교한 가운데 값을 다시 비교할 필요가 없기 때문입니다.

이진 탐색은 조건이 충족되면 매우 적은 횟수의 비교로 답을 찾을 수 있습니다. 그러나 **정렬된 배열**이어야 하며, 정렬 작업 자체에도 시간이 든다는 점은 별개입니다.

## 6. 한 눈에 보는 탐색 비교

| 기준 | 순차 탐색 | 이진 탐색 |
|---|---|---|
| 정렬 필요? | 아니요 | 예 |
| 시작 위치 | list[0] | 가운데 mid |
| 다음 단계 | i를 1 증가 | low 또는 high 수정 |
| 원하는 값 찾으면 | 인덱스 반환 | 인덱스 반환 |
| 없으면 | -1 | -1 |
| 비교 횟수 | 최대 SIZE회 | 한 번마다 범위가 대략 절반으로 줄어듦 |

예를 들어 정렬된 값이 [3,7,12,16,25,39,48,57,68,80]이고 **57**을 찾을 때:

| 회차 | low | high | mid | 검사값 | 다음 단계 |
|---|---:|---:|---:|---:|---|
| 1 | 0 | 9 | 4 | 25 | 57이 더 크므로 low=5 |
| 2 | 5 | 9 | 7 | 57 | 찾음, 7 반환 |

순차 탐색은 원래 순서에 따라 57을 더 빨리 찾을 수도, 더 오래 걸릴 수도 있습니다. **한 번만 탐색할 때 정렬하는 비용까지 포함해 무조건 이진 탐색이 빠르다고 말하면 부정확**합니다.

## 7. 중복값이 있을 때 주의할 점

같은 값이 두 번 있다면 두 검색 함수가 가리키는 인덱스는 다를 수 있습니다. 순차 탐색은 **정렬 전 배열에서 처음 등장한 위치**를 반환합니다. 이진 탐색은 **정렬 후 배열에서 도중에 일치한 위치**를 반환합니다.

두 결과가 달라도 찾으려던 숫자가 실제로 그 인덱스에 들어 있다면 정답입니다. 현재 코드는 '모든 중복 위치 나열'이 목표가 아닙니다.

## 8. 원본과 응용판의 차이

| 기존 원본 | 8~11장 응용판 | 변경 의도 |
|---|---|---|
| 생성·출력·정렬·이진 탐색 | 순차 탐색 추가 | 정렬 필요 여부 비교 |
| BinarySearch 함수 안에서 검색값 입력 | main에서 검색값 입력 | 입력 책임과 계산 책임 분리 |
| 탐색 함수가 직접 결과 메시지 출력 | 위치 또는 -1 반환 | 함수의 반환값 이해 |
| 함수 네 개 | 함수 다섯 개 | 필요한 기능을 추가 |
| 단순 헤더 선언 | 중복 포함 방지 사용 | 여러 소스 파일의 선언 관리 연습 |

## 9. 8~11장 개념 대응

| 단원 | 실제 활용 |
|---|---|
| 8장 함수 | 선언, 정의, 호출, 매개변수, return |
| 9장 변수 범위와 재귀 | 일반 함수 내부 변수만 사용. 재귀는 반복문보다 필요성이 낮아 사용 안 함 |
| 10장 배열 | 선언, 순회, 비교, 선택 정렬, 순차·이진 탐색 |
| 11장 포인터 | 배열 인자를 통한 원래 배열 접근, scanf의 & 연산자 |

**전역변수는 없습니다.** #define SIZE는 전처리 상수이고, function.h의 함수 원형은 '전역으로 공유하는 데이터'가 아닙니다.

## 10. 교수님 예상 질문과 답변

**Q1. 왜 두 가지 탐색을 모두 넣었나요?**  
A. 순차 탐색은 정렬 없이 사용할 수 있지만 이진 탐색은 정렬이 필요하다는 차이를 직접 비교하려고 넣었습니다.

**Q2. 왜 원본과 달리 key를 main에서 읽나요?**  
A. 동일한 숫자를 두 탐색에 전달해 비교하기 위해서이며, 탐색 함수가 입력까지 담당하지 않게 역할을 나눴습니다.

**Q3. -1이 뜻하는 것은요?**  
A. 검색 실패입니다. 배열 인덱스는 0부터 시작하므로 -1은 정상 위치가 될 수 없습니다.

**Q4. 왜 이진 탐색 전 정렬해야 하나요?**  
A. 가운데 값과의 비교로 왼쪽 또는 오른쪽 절반을 버리는 판단은 숫자들이 정렬되어 있을 때만 옳기 때문입니다.

**Q5. 함수에 list를 넘길 때 값 열 개가 복사되나요?**  
A. 아닙니다. 배열 매개변수는 호출한 배열의 원소에 접근하는 방식이라 원래 배열이 정렬됩니다.

**Q6. 왜 min은 값이 아니라 위치를 저장하나요?**  
A. 최솟값을 찾은 다음 해당 위치와 현재 위치를 교환해야 하므로 인덱스가 필요합니다.

**Q7. 어떤 탐색이 항상 빠른가요?**  
A. 어느 것도 항상 빠르다고 단정할 수 없습니다. 이진 탐색은 비교 횟수가 적지만 먼저 정렬해야 할 수도 있습니다.

**Q8. 헤더는 왜 필요한가요?**  
A. main.c에서 function.c에 구현된 함수의 선언을 알 수 있게 하기 위해서입니다.

**Q9. 검색 숫자가 배열에 없으면 어떻게 되나요?**  
A. 순차 탐색은 끝까지 확인하고 -1 반환, 이진 탐색은 low가 high보다 커질 때 -1을 반환합니다.

**Q10. 왜 재귀 호출을 사용하지 않았나요?**  
A. 이번 문제는 반복문으로 직관적으로 해결됩니다. 재귀를 억지로 넣으면 호출 순서를 이해하기 어려워질 수 있기 때문입니다.

## 11. 실행과 과제 시연 점검

표준 C 컴파일러를 사용할 경우 세 파일 중 **main.c와 function.c를 함께 컴파일**해야 합니다.

~~~sh
gcc -std=c11 -Wall -Wextra main.c function.c -o arraysearch
~~~

- 헤더는 #include로 처리하므로 명령의 별도 입력 파일로 주지 않습니다.
- 프로그램이 실행되면 0~99 범위의 난수 열 개가 출력됩니다.
- 화면에 보이는 숫자 **하나를 입력**하여 두 탐색에서 모두 찾아지는지 확인해 보세요.
- **100을 입력**하면 난수 범위 밖이므로 두 탐색이 모두 찾지 못합니다.
- 매번 생성하는 난수가 달라져도 정상입니다.
